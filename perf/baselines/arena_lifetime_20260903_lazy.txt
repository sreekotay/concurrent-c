arena_lifetime_bench — 2026-09-03 — Linux x86_64 (4 cores), gcc -O2 (ccc build --release), ROUNDS=5 best-of
Branch: lazy checkpoints. Compared against HEAD = becf2e3 (per-slab records,
lock-free bump, eager child carve per checkpoint; receipt
arena_lifetime_20260903_slabs.txt).

What changed:
- A checkpoint is a mark on the host: the slab word, a fresh epoch that
  every bump above it carries, and the head of the record list. Bumps keep
  going on the host's own slab. Restore runs the records attached since,
  then returns the slab word to the mark in one CAS. The tip never drops
  below a mark (a pre-mark object at the tip released during scratch is a
  hole), so the mark's snapshot is always the tip to return to.
- The mark becomes a child host only when it must: scratch outgrows the
  slab or spills, a pre-mark object must move, parent-side storage is
  needed, or marks nest past CC_ARENA_MARK_DEPTH (3). Promotion turns the
  range above the outermost mark into the child's L1 in place, parks the
  host tip, and moves the inner marks and scratch records over. From then
  on the previous machinery runs unchanged and restore frees the child.
- The first mark lives in the host (host is 232 bytes); the next two come
  from the host's slab at the first nested checkpoint, as scratch of the
  outer mark. A checkpoint always arms on a live host.
- Owner headers, attached records, and a moved payload's epoch resolve to
  the host whose bytes hold them, whichever handle they were created
  through (an owner made in scratch before a promotion is the child's).
- Ownership resolution and release check every slab on the active chain
  before any host's overflow, so a pointer at the start of a child's slab
  is never peeked at as if it were the parent's overflow header.
- Live counts after a lazy restore or a promotion only ever over-count
  (a pre-mark release during scratch), which can only defer a rewind.

Notes:
- An empty checkpoint cycle is now two lock acquisitions, one epoch
  fetch-add, and one CAS: about 40 ns against 63 for the eager carve and
  68 for the original snapshot model, with the same guarantees as the
  carve. The lock stays because promotion is triggered by any thread's
  slow path and must see a consistent mark stack.
- The @scratch shape (a string template) is 71 ns; the 2 MiB-scratch row
  now pays a promotion (malloc of a child host) and is still 30 percent
  cheaper than the eager carve, since the carve paid on every capture.
- Everything that is not a checkpoint is flat; the contended rows moved
  with machine noise.
