arena_lifetime_bench — 2026-09-03 — Linux x86_64, gcc -O2 (ccc build --release), ROUNDS=5 best-of
Branch: same lifetime model as arena_lifetime_20260903.txt, plus two fast paths:
  (1) String append is inline: a fitting append (inline handle with room, or a
      heap owner whose token matches and whose capacity covers the bytes) is a
      copy, a length bump and a NUL; only growth calls the runtime. The string
      face's byte helpers are builtins (memcpy / memset / strlen) on GCC and
      Clang, so a literal append is a pair of moves.
  (2) Every counter under meta_lock (offset, live_allocs, overflow_bytes) is a
      relaxed atomic; the lock is an acquire CAS and a release store; the
      locked live-count step is a load and a store, not a read-modify-write.
      Slab descriptor fields that grow rewrites (base, capacity, tail_carved,
      prev, _flags) are published with release stores and read unlocked
      through relaxed / acquire loads, so the ownership and liveness hints
      are defined reads (TSan-clean on the adversarial and storm programs).

Notes:
- The shared bump path is now cheaper than glibc's tcache pop. What it
  still pays over the exclusive path is the lock word: one CAS in, one
  release store out.
- Every path that takes the lock once (release, tip pop, hole, reuse pop,
  tip realloc, owner rebirth) lost 25 to 60 ns: those were the sequentially
  consistent stores and the read-modify-writes on the live count. Checkpoint
  cycles take the lock two or three times and lost proportionally.
- String append: with room in the backing, one append measures about 3 ns
  in a standalone loop (7 to 8 ns with the byte-loop copy, 22 ns through
  the runtime call). The benchmark row grows one string to 12 MB on an 8 MiB
  heap arena, so it is dominated by regrow copies past the slab and by the
  first touch of the grown extents; the C twin's realloc remaps at that size
  and copies nothing. The remaining gap on that row is growth policy, not
  the append.
- Vec push was already inline and is unchanged. Owner churn dropped with the
  single-lock header + payload path getting cheaper; the registry birth and
  kill (about 28 ns of every owner cycle) are untouched.
